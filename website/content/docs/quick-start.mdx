## Installation [#install]

Use your package manager of choice. linkpeek runs on Node.js 22.12+, Bun, Deno and fetch-compatible edge runtimes, ships ESM and CommonJS with TypeScript declarations, and has one runtime dependency.

```package-install
linkpeek
```

### With a coding agent [#agent]

Paste this task into Claude Code, Cursor, Codex or Copilot. It installs linkpeek, adds a server endpoint and a card component, and follows the safety rules below. Agents can also fetch it from [prompt.md](/prompt.md).

## Usage [#example]

```ts
import { preview } from "linkpeek";

const result = await preview(
  "https://example.com/article"
);

if (result.statusCode < 400) {
  console.log(result.title);
  console.log(result.description);
  console.log(result.image);
}
```

### What you get [#result]

This is linkpeek parsing this page, live in your browser. `preview()` returns the same shape for a fetched URL.

<LiveResult />

Missing metadata returns `null`. HTTP error pages can still return metadata, so check `statusCode` before caching a result. The [API reference](/api/) lists all options, result fields and error codes.

## Where it runs [#where]

| Where | preview(): fetch and parse | parseHTML(): parse only |
| --- | --- | --- |
| Server or API route (Node.js, Bun, Deno) | Yes | Yes |
| Edge (Cloudflare Workers, Vercel) | Yes | Yes |
| Browser | No: browsers may not read other sites' pages | Yes |

Browsers block a page from reading the HTML of another site (CORS). That is why Slack, Discord and X build their previews on a server. Your frontend works the same way: it sends the URL to your own endpoint, the endpoint calls `preview()`, and returns the fields as JSON. The demo on the homepage is built exactly like that. The [Next.js guide](/integrations/nextjs/) shows the endpoint.

## Parsing existing HTML [#parse-html]

Use `parseHTML(html, baseUrl)` when you already have the HTML. It runs synchronously without network requests. See the [Open Graph parser guide](/guides/open-graph-parser/) for examples and an optional [interactive parser](/guides/open-graph-parser/#try).

## Presets [#presets]

The default fast preset scans the document head and retains up to 30,000 decoded response-body bytes. The quality preset allows 200,000 bytes, scans body JSON-LD and image fallbacks, and can follow one validated meta-refresh.

```ts
import { preview, presets } from "linkpeek";

const result = await preview(url, presets.quality);
```

These limits apply to retained bytes, not total network traffic.

## Performance [#performance]

Most metadata lives in the `<head>`. The default preset stops reading there and cancels the rest of the response, so most of a large page is never downloaded or parsed. The [benchmarks](/benchmarks/) measure this against five other packages.

## Security and limitations [#boundaries]

linkpeek validates redirect targets and blocks literal private and non-global addresses by default. The runtime’s `fetch` resolves hostnames; on Node.js pass `resolveHost` to check DNS answers on every hop, and give public endpoints outbound network controls. Never forward caller credentials to arbitrary URLs. Read the [security model](/security/) before exposing an endpoint.

linkpeek does not execute page JavaScript, extract full articles or fetch oEmbed payloads. See [troubleshooting](/guides/troubleshooting/) for missing metadata and HTTP errors, or the [library comparison](/guides/link-preview-library-comparison/) for other use cases.
