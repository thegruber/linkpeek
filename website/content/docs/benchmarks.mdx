linkpeek and five other link preview packages, measured on <BenchmarkDate /> with the same pages, the same local server and the same correctness check. Every number comes from an open harness you can run yourself.

<BenchmarkHighlights />

## Large pages [#large-page]

Each package previews the same 500 kB page whose metadata sits in the `<head>`. linkpeek stops reading after the head and cancels the response stream, so most of the body is never read or parsed.

<BenchmarkChart kind="large" />

## Small pages [#small-pages]

On small pages the differences are a fraction of a millisecond and real network latency dominates. `unfurl.js` was faster than linkpeek on every small fixture in this run.

<BenchmarkChart kind="small" />

## Install footprint [#size]

linkpeek has one runtime dependency, `htmlparser2`. Smaller installs matter most for serverless cold starts, container images and edge bundles.

<BenchmarkChart kind="install" />

## Bytes read from a 500 kB page [#stream]

The local stream probe serves a controlled 500 kB response in 1 kB chunks and records how much the parser requested.

| Mode | Source bytes requested | Configured ceiling | 500 kB page |
| --- | --- | --- | --- |
| **Fast** (default) | **2 kB** | 30 kB | Stops after `</head>` |
| Quality | ~202 kB | 200 kB | Continues for body fallbacks |

“Source bytes” includes one queued 1 kB stream chunk; the retained byte ceiling remains exact. These are requested chunks, not exact network wire bytes.

## Try it [#try]

```bash
npm install linkpeek
```

The [quick start](/quick-start/) has a complete example. The [library comparison](/guides/link-preview-library-comparison/) covers what each package is best at, including the cases where another one fits better.

## Method [#method]

<BenchmarkMethod />

Timings depend on hardware: an earlier run on Apple silicon measured lower absolute numbers with the same ordering on the large page. The [comparison notes](https://github.com/thegruber/linkpeek/blob/main/docs/comparison.md) keep every dated result, and the [raw JSON runs](https://github.com/thegruber/linkpeek/tree/main/benchmarks/competitive/results) include commit and environment details.

## Run the benchmarks [#reproduce]

```bash
npm ci
npm run benchmark

npm run build
cd benchmarks/competitive
npm ci
npm run bench -- --json
```

The competitive lockfile pins every compared version, and every timed preview must extract the expected title. Live benchmarks are network smoke tests, not competitive evidence.
