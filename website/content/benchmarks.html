Link preview benchmarks

linkpeek and five other link preview packages, measured on {{benchmark:date}} with the same pages, the same local server and the same correctness check. Every number comes from an open harness you can run yourself.

{{benchmark:summary}}

Large pages

Each package previews the same 500 kB page whose metadata sits in the <head>. linkpeek stops reading after the head and cancels the response stream, so most of the body is never read or parsed.

{{benchmark:large}}

Small pages

On small pages the differences are a fraction of a millisecond and real network latency dominates. unfurl.js was faster than linkpeek on every small fixture in this run.

{{benchmark:small}}

Install footprint

linkpeek has one runtime dependency, htmlparser2. Smaller installs matter most for serverless cold starts, container images and edge bundles.

{{benchmark:install}}

Bytes read from a 500 kB page

The local stream probe serves a controlled 500 kB response in 1 kB chunks and records how much the parser requested.

Method

The packages run on a local server, so these numbers isolate library overhead; they do not predict latency against real websites. {{benchmark:method}} Environment: {{benchmark:environment}}. Versions: {{benchmark:versions}}.

Timings depend on hardware: an earlier run on Apple silicon measured lower absolute numbers with the same ordering on the large page. The comparison notes keep every dated result, and the raw JSON runs include commit and environment details.

The competitive lockfile pins every compared version, and every timed preview must extract the expected title. Live benchmarks are network smoke tests, not competitive evidence.
